# TransAmerica Trail Tracker

A cycling trip tracker/dashboard styled after the Artemis II mission tracker (artemis-ii-tracker.com). The humor is intentional — applying NASA mission-control aesthetics to a bicycle trip.

## Route

- **Direction**: Yorktown, VA → Astoria, OR (eastbound → westbound, i.e. the "WB" direction)
- **Total distance**: ~4,198 miles (computed from GPX; Adventure Cycling advertises 4,205)
- **GPX source**: 12 Adventure Cycling WB section files (`TA_01_WB_Main_*.gpx` … `TA_12_WB_Main_*.gpx`)
- **Processing**: sections are concatenated in reverse file order (12→1) without reversing individual trackpoints, since the files are already westbound

## Architecture

- **API**: Node.js + Express + SQLite (`better-sqlite3`), runs on port 3000
- **Frontend**: vanilla HTML/CSS/JS served by nginx
- **Reverse proxy**: nginx — locally on port 8080; in production (`docker-compose.prod.yml` overlay) on ports 80 (HTTP→HTTPS redirect) and 443 (SSL termination via Let's Encrypt certs mounted from the host)
- **Data**: SQLite database persisted in a named Docker volume (`api-data`)
- **No local Node.js required** — everything runs in Docker

## Testing

Run all tests after making changes:

```bash
cd api && go test ./...
```

## Running locally

```bash
cp .env.example .env          # set CHECKIN_PASSWORD
make up                       # build and start (http://localhost:8080)
make gpx                      # regenerate route-data.js from GPX files
make down                     # stop
make reset                    # stop and wipe all check-in data
```

## Check-ins

- Submitted via `/checkin.html`, protected by `CHECKIN_PASSWORD`
- Weather is auto-fetched from Open-Meteo (free, no API key) using the check-in coordinates
- Fields: location (name, lat/lng/town/state, elevation), daily stats (miles, speed, elevation gain/loss, moving time), lodging type, rest day flag, note, optional photo URL
- `name` is an optional free-text field for the specific place (campsite, hotel, host, etc.); displayed on the dashboard as `"Name · Town, State"` when present

## Design decisions

### Header / layout
- Desktop header shows only the title, subtitle, and status pill — the four stat items (Rider, Elapsed, Location, Complete) were removed; those values live elsewhere in the UI
- Mobile hides header stats via CSS (`@media max-width: 768px`)
- Current Position sidebar panel shows: Location (`"Name · Town, State"` or `"Town, State"`), Elevation — Mile Marker and Miles Remaining were removed

### Theme
- Artemis II mission-control aesthetic: dark panels, cyan accents, monospace numbers, `Rajdhani` headings
- Map uses **CartoDB Voyager** tiles (light, high-contrast, readable state lines) — earlier attempts with CartoDB Dark Matter had poor label contrast even with CSS brightness filters
- The light map / dark panels contrast is intentional and reinforces the "mission control monitoring something out there" feel
- A GeoJSON state boundary overlay was tried and removed — Voyager's built-in state lines are sufficient

### Map
- Route line: unridden portion `#7ab0d0` weight 3; completed portion `#0055cc` weight 4
- Start/Finish labels: `#003399` (deep navy) with a white text-shadow halo for legibility on the light map
- Rider position marker: bright green (`#00ff9d`) pulsing dot

### Elevation profile
- Uses `ROUTE_ELEVATION` array generated from GPX `<ele>` tags (sampled every ~8km → ~842 points)
- X-axis is **reversed** (Astoria on left, Yorktown on right) to match the map's geographic orientation
- Falls back to plotting elevation at each check-in point if `ROUTE_ELEVATION` is not present

### route-data.js
- Generated by `make gpx` / `tools/process-gpx/main.go` — do not edit by hand
- Map track sampled every ~2km (~3,314 points); elevation profile sampled every ~8km (~842 points)
- `ROUTE_TOTAL_MILES` reflects the actual GPS-computed distance (~4,198.5 miles)
- `ROUTE_SECTIONS` boundaries are computed from GPS data, not hand-coded

### CSS contrast
- Dark theme variables: `--text: #eaf4ff`, `--text-dim: #7abcd8`, `--text-label: #90cce8`
- Borders: `rgba(0, 210, 255, 0.35)` — earlier value of 0.18 was too subtle
- Panel backgrounds are near-black (`rgba(2, 8, 20, 0.97)`) for maximum text contrast
